# Amphibious leg attachments

A separate unarmed MuJoCo scene demonstrates walking into a calm basin, extending the front legs and their attached floats, floating across, and walking up the opposite bank. Smooth 15.2° ramps keep attention on the attachments and support transition. The rocks were removed at the user's request.

The robot is the MuJoCo Menagerie **Unitree Go2 physical model**, used as a stand-in. Menagerie does not supply the walking controller used here. This demo uses a custom slow crawl with inverse kinematics, measured-state feedback, contact checks, gravity/contact feedforward, and torque-limited joint tracking. It is a scripted demonstration on known terrain, not Unitree's production gait or a learned locomotion policy.

## Run and watch

```sh
git lfs pull
uv sync --locked
uv run amphibious view
# 1: follow; 2: side; 3: overview; 4: front; Space: pause
# Default playback is 8x. Use --speed 1 for real time.
uv run amphibious view --static
uv run amphibious preview
uv run amphibious run
uv run amphibious record --speed 8
uv run pytest -q
```

The macOS launcher automatically invokes `mjpython` and supplies the uv Python library location. No ROS, CUDA, MuJoCo Warp, or separate FFmpeg installation is needed. MuJoCo simulates rigid bodies on the CPU; its renderer produces camera images. The front camera is mounted on the body and can go below the waterline. It is a rendering camera, not a perception input.

[Complete three-view video](../../previews/amphibious/crossing.mp4) · [Static scene](../../previews/amphibious/overview.png) · [Close-up](../../previews/amphibious/detail.png)

The video replays the complete saved physical trajectory with simultaneous following, side, and overview cameras. Walking plays at 8×; flotation and its surrounding transitions slow to 2×, with the current speed labeled. It displays measured buoyancy, weight, foot contacts and applied water thrust. Replay assigns recorded poses solely to render the already-simulated trajectory. The live simulation advances its free chassis through forces and contacts, without moving it by assigning poses.

## Physical assumptions and limits

| Property | Value / rationale |
| --- | --- |
| Robot mass | Vendor Go2 15.206408 kg; four 0.45 kg capsules add 1.8 kg; total 17.006408 kg |
| Capsule geometry | Radius 0.085 m, straight section 0.20 m, overall length 0.37 m; about 7.11 L each |
| Capsule mount | Rigid child of each thigh; 0.14 m lateral offset and 0.07 m below thigh origin; no separate deployment joint |
| Leg abduction limits | ±1.0472 rad, inherited from Go2 |
| Front thigh limits | −1.5708 to 3.4907 rad, inherited |
| Rear thigh limits | −0.5236 to 4.5379 rad, inherited |
| Knee limits | −2.7227 to −0.83776 rad, inherited |
| Motor torque caps | Abduction/thigh ±23.7 N·m; knee ±45.43 N·m, enforced in controls and actuator force limits |
| Joint tracking | 120 N·m/rad proportional and 4 N·m·s/rad damping, plus gravity/contact feedforward, clipped to motor limits |
| Floating posture | Front: abduction 0, thigh −1.50, knee −0.90 rad; rear: 0, 1.30, −2.50 rad |
| Front float direction | Approximately 99.7% forward, 7.1% downward relative to the body; floats rotate with the upper legs |
| Basin | Bed −0.38 m, waterline −0.14 m; 0.24 m central water depth; each ramp 1.4 m long |
| Contact | Foot `solref` 0.01/1 and `solimp` 0.95/0.99/0.001, replacing the vendor's soft foot contacts to prevent excessive penetration; terrain sliding friction 1.0 |
| Integration | 2 ms `implicitfast`; control at 100 Hz; fluid forces recomputed at 500 Hz |
| Idealized propulsion | Two body-mounted water thrusters, each capped at ±6 N and gated by immersion |

Float mass and dimensions are illustrative design assumptions. Original robot inertials and joint limits are retained; float child bodies add their own mass and capsule inertia. Decorative straps, brackets and thruster shells have zero additional mass; their mass is included in the attachment allowance.

Buoyancy is calculated from sampled submerged capsule volume and an assumed sealed central hull: **F = ρ g Vsubmerged**, with freshwater density 1,000 kg/m³. Each resultant acts at the corresponding center of submerged volume, so buoyancy also generates roll/pitch moments. Samples are normalized to the exact capsule volume, with a 25 mm smooth transition at the waterline. The sealed hull displaces about 4.01 L. This waterproofing assumption does not assert that a real Go2 is amphibious.

Point drag is `−f(7v + 12|v|v)` and angular drag is `−f(0.20ω + 0.10|ω|ω)`, where `f` is submerged fraction. These dissipative coefficients are qualitative, not calibrated tank measurements. Water thrust uses simple forward-speed and heading feedback; it is not generated by simulated propellers or paddling legs. No external propulsion is applied on dry land.

MuJoCo handles rigid-body dynamics and contact; this project adds localized buoyancy and drag. There is no fluid mesh, CFD, waves, wakes, splashes, water ingress, or deformable/inflatable float model. The reference video motivates the attachment motion, not a claim of matching NAUT or V60 engineering performance. See [MuJoCo's fluid-force documentation](https://mujoco.readthedocs.io/en/stable/computation/fluid.html) for the distinction from its built-in global-medium force models.

## Validation and provenance

Tests compare the controller's terrain heights with rays cast against the actual ramp meshes; verify the front float direction and joint limits; check displaced-volume force and dissipative drag; compare floating with buoyancy disabled; and run the complete crossing, including unsupported flotation and four-foot dry completion. Existing hexapod and rover tests remain in the suite.

Validation on Apple Silicon macOS: **20 tests passed** (16 existing plus 4 new), the native viewer smoke test passed, and all 22 vendored file hashes matched. The final H.264 video is 1920 × 1080 at 25 fps, 1,712 frames / **68.48 seconds**, and its complete stream decoded without errors. Entry, floating, ascent and final frames were visually inspected. See `VIDEO.json` for capture metadata.

The isolated still-water check balances 166.84 N buoyancy against 166.83 N weight with no bottom contact. Disabling buoyancy makes the robot sink approximately 10.6 cm onto the basin floor. See `REPORT.json` for the full crossing metrics.

The complete run takes **446.0 simulated seconds**, including a three-second final settle. It records **10.816 seconds of continuous unsupported flotation**, completes with four foot contacts and zero buoyancy on the far bank, and produces no MuJoCo warnings. Peak motor use reaches the specified torque caps; maximum ground penetration is 6.9 mm and maximum body tilt is approximately 16.9°. The rear-left float briefly enters the entry ramp's contact proximity; the capsules remain physical collision shapes. The finish threshold is crossed at 443.0 s, followed by approximately 4 cm of backward settling on the dry bank.

During development, soft vendor foot contact caused sinking, an inconsistent ramp-height calculation disrupted ascent, and open-loop foot references accumulated false forward progress. The controller now re-anchors the gait to the measured body and restarts its stepping order after swimming. For the wet exit, it requests 0.34 m leg clearance to reach the bed and recover foot load before returning to the 0.30 m walking clearance. These are scene-specific control choices; this single crossing does not establish robustness on unfamiliar terrain or under disturbances.
